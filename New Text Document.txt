Fresh Trade Engine

I want to build fresh trade engine that is capable of running any kind of complex strategies. fault proof architecture. component based micro service architecture so one does not affect another if anything goes wrong while sharing same database.

Phase 1
-- Feed Manager (Micro Service)
   -- Support Broker. IIFL XTS, SHOONYA, FYERS (Automatic Switch on failover based on priority set)
   -- Support these segment NSE, NFO, BSE, BSEFO, MCX, MCXFO
   -- In First Phase cover XTS and SHOONYA only
   -- Default subscription, NIFTY, BANKNIFTY, SENSEX, (CRUDEOIL, NATURALGAS, GOLD, SILVER -> Current Month Future) Future should change automatically on next day of expiry.  
   -- Feed Consumer - Frontend and Strategy Manager

Phase 2 (Independent Module)
-- Broker Order Manager
   -- Support Broker, XTS, KOTAKNEO, SHOONYA, ZERODHA, DHAN, FYERS
   -- Solid Order Reconcile via Socket and Webhook wherever supported and applicable.
   -- Universal symbol mapping across all broker. 

Phase 3
-- Strategy Manager (Independent Module) Each strategy should be separate from each other. 
   -- I want a strategy to run on own container so it get never disturb other strategy when new strategy added or other strategy code updated.
   -- One strategy can map to multiple broker/client and fire order in parallel.
   -- There should be option to duplicate strategy in cases when we need to run with different parameter or different symbols. main logic will be same.

Since, all three components will run on same server and codebase it will be easier so they can communicate with each other locally instead of web api. Use web api for frontend and for component communication local api path so save network latency.
